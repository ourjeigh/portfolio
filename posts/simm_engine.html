SiMM Engine

I've been building a 2D game engine from the bottom up to better understand its various components. My primary rules for development have been 1) to make everything from scratch (no std or external libraries) and 2) develop with multiplatform support in mind.

The video above shows the very limited player-facing functionality I've built: basic game flow from logo to menu and individual demo scenes, a few simple one-shot sounds, basic player and camera control, and rudimentary collision detection. Under the hood, there are a lot of custom-built systems in place to support that functionality:
  • Software Graphics Renderer
  • Audio Renderer
  • File IO
  • Memory Allocation
  • Asset System
  • Bitmap & Text Rendering
  • Data Structures
  • Logging and String Formatting
  • Perf Measurement
  • State Machine
  • Camera

With inspiration from Handmade Hero, I've built the game layer of the engine as a dll to allow for hot reloading of the game code while the engine is running. This involves splitting the application into a statically linked engine layer and a dynamically linked game layer. The engine loads the game dll explicitly and points it to the pre-allocated game memory. When a new dll is detected, it unloads the existing dll, loads the new one, and fixes up the memory so that state is preserved.

This approach to the game layer means that all game state must be stored in the memory block provided by the engine (no static globals). It also means that game state needs to be comprised of fairly pure data types. Any polymorphic object containing a vtable cannot be stored in the game state, since those vtable pointers will not be preserved accross a dll reload. Generally, I've found these requirements to be good: it forces me to separate functionality from state.

The video above shows an example of modifying the game code and then live reloading to see the effect. In this case, I change the length and color of the collision normal debug line. An in-game hotkey triggers the reload so that this approach could be used to simulate a scripting workflow.
